01 · Architecture

From raw data to dashboard: the six-stage journey

Every Power BI report you will ever build — a Swiggy orders dashboard, a bank's loan-risk report, a hospital's bed-occupancy tracker — moves through the exact same six stages. Learn this once, and the whole tool stops feeling random.

Kitchen analogy: Data Sources are raw ingredients. Power Query is washing and chopping. The Data Model is the recipe linking ingredients together. DAX is the cooking method and measurements. Visuals are the plating. The Service is serving the finished dish to your guests.

Every stage, explained

① Data Sources

Where raw data physically lives before Power BI touches it — an Excel export, a company SQL Server database, or a public webpage. Nothing is clean yet.

Example: A Zomato analyst's data source might be an Excel export of last month's orders.

② Power Query

The cleaning layer — remove duplicates, fix spelling, split columns, handle blanks. Real data is never clean; this is where you make it usable.

Example: Standardizing "bangalore", "Bangalore", "BANGALORE " into one clean value.

③ Data Model

Where cleaned tables get connected through relationships — the same job as VLOOKUP in Excel, but automatic and drawn once for the whole report.

Example: Linking a bank's Loans table to its Customers table by Customer ID.

④ DAX

The formula language — Excel formulas' cousin, built for whole tables instead of single cells. This is how you create numbers that don't already exist as a column.

Example: Profit = SUM(Sales) − SUM(Cost), recalculated instantly however you slice it.

⑤ Visuals & Reports

The charts, maps, and tables you actually see — built in Report View. This is the "plating" step, turning numbers into a picture a human reads in five seconds.

Example: "Top 5 restaurants by revenue" becomes a bar chart.

⑥ Dashboards & Service

Desktop is where you build. The Power BI Service (cloud) is where you publish and share — a Report is multi-page and lives in Desktop; a Dashboard is a single-page pinboard that lives only in the Service.

Example: Your CEO opens your published dashboard on their phone during a flight layover.

Gateways & refresh

A Gateway is a small piece of software that lets Power BI Service securely reach data sitting inside a private company network — like a sales database that never touches the public internet — so it can refresh automatically. Refresh is simply re-pulling the latest data so your numbers stay current: manual (click Refresh) or scheduled (e.g. every night at 6 AM).

Import vs. DirectQuery vs. Live Connection

Three ways Power BI can connect to data. For this whole course — and almost everything you'll do as a beginner — you'll use Import.

02 · The Interface

Six zones. Once you can name them, you can navigate them.

Power BI Desktop looks intimidating for about twenty minutes. Every screen you'll ever see is built from the same six zones below — learn the map once.

ZonePurposeWhen you use it
① Ribbon
Home · Insert · Modeling · View		Home = Get Data, Refresh, Publish. Insert = logos, text, buttons. Modeling = relationships & DAX measures.Home starts every session; Modeling whenever tables need linking or a calculation is needed.
② Report CanvasThe blank page where visuals are placed and arranged.Every time you design what the dashboard looks like.
③ Visualizations PaneThe palette of chart types — bar, pie, line, map, and 30+ others.Anytime you want to add a new chart.
④ Fields PaneEvery table and column available — your ingredient list.Constantly — you drag from here onto every chart you build.
⑤ Filters PaneRestricts what data shows, on one visual, the page, or the whole report — without deleting anything.To focus a view, e.g. "2025 only" or "exclude cancelled orders."
⑥ Page NavigationTabs at the bottom to switch between report pages, plus the Report / Data / Model view switcher.Multi-page dashboards; switching to Data View to sanity-check a column, or Model View to check relationships.
Common mix-up: Model View is only for relationships — it is not where you build charts. That's Report View. Students confuse these two constantly in week one.

03 · Connecting to Data

Getting your data into Power BI — three ways

Excel, a company database, or a public website — the click-path is almost identical every time: Get Data → pick a source → Navigator → Transform Data.

Connecting to Excel

Home→Get Data→Excel Workbook→select file→Navigator (tick sheet)→Transform Data
OptionWhat it doesWhen to use
LoadBrings data in exactly as-is, no cleaning.Only when you're 100% sure the data is already clean — rare in real life.
Transform DataOpens Power Query first so you can clean before it touches your report.your default click, always
CombineStacks multiple files/sheets with the same structure into one table.Your company saves one Excel file per month and you want all 12 as one table.
Golden rule: Always click Transform Data, never Load, unless you've already inspected the data and know it's clean.

Connecting to SQL Server

A SQL Server is a very large, very organized Excel workbook that lives on a powerful shared computer instead of your laptop — it can hold billions of rows, many people can use it at once, and it's always "live."

Server Name

The address of the machine where the database lives, e.g. salesdb.company.com. Like a building address.

Database Name

The specific database on that server, e.g. SalesDB. One server can host many databases — like flats in a building.

Authentication

Windows Authentication (your company login, automatic) or Database Authentication (a separate username/password).

Connection String

Server + database + settings bundled into one line, e.g. Server=salesdb.company.com;Database=SalesDB;

Import vs. DirectQuery vs. Live Connection

Full comparison is on the Architecture page — the short version: use Import for this entire course and for almost everything you'll do as a beginner.

Connecting to Web Data

Home→Get Data→Web→paste URL→OK→Navigator→Transform Data

Works on any public page with an HTML table — Wikipedia country/state data tables, government open-data portals (data.gov.in), public COVID dashboards, weather data. Power BI scans the page and lists every table it finds as Table 0, Table 1… — preview each one before loading to make sure you picked the right one.

Real limitation: if the website changes its table layout later, the connection can break. This is a genuine trade-off of web scraping, not a bug in Power BI.

05 · Visualizations

Eight charts. One rule: every chart answers a business question.

If you can't say what question a chart answers, don't build it. Click any card below to see steps, formatting, best practices, and common mistakes.

Which chart, when?

Business questionChartAvoid when…
Compare a number across categoriesBar ChartMore than ~10–12 categories
Show parts of a wholePie ChartMore than 5 categories (Rule of 5)
Show change over timeLine ChartComparing unrelated categories
Show one critical headline numberKPI CardYou need more than 4–6 things at once
Show progress toward a goalGauge ChartComparing multiple items at once
Show relationship between two numbersScatter PlotOnly one number available, <10 points
Show geographic distributionMapPrecise comparison matters more than location
Show hierarchy + proportion togetherTree MapOnly one category level exists

The eight charts, in depth

Formatting that makes it look professional

Theme

One click applies a consistent palette + font to the whole report. Pick it first, build after.

Real titles

Never ship "Sum of Sales by Category." Rename to what a CEO understands in 2 seconds.

Data labels

On for Bar/Pie/Card. Usually off for dense Line/Scatter — labels overlap into noise.

Conditional formatting

Red/green rules on tables and KPIs so problems jump out without reading every number.

Tooltips

Extra detail on hover without permanently cluttering the chart.

Interactions

Click one visual, watch the others filter — Power BI's biggest "wow" moment, on by default.

07 · Capstone

Your first day as a Business Analyst Intern

"Attached is our raw sales data. Board meeting is tomorrow morning. I need a one-page dashboard, and I need YOU to walk me through 3 insights before I present." — that's the whole brief. That's also almost word-for-word what a real first assignment looks like.

Deliverable checklist

  • ✓
    Data imported from Sales_Dirty.xlsx
  • ✓
    All data-quality issues cleaned in Power Query — zero errors, zero unexplained blanks, zero duplicate rows
  • ✓
    At least 4 KPI Cards: Total Sales, Total Profit, Total Orders, Average Order Value
  • ✓
    At least 4 chart types, each answering a clear business question
  • ✓
    Consistent theme, real titles, interactions tested
  • ✓
    3 spoken insights, each backed by a specific number

The insight template

Every insight follows this exact sentence structure:

"[Business fact] is happening in [specific area], shown by [specific number/chart], which suggests [business implication]."

Model example: "Electronics is our strongest category, generating roughly ₹9.2 lakh — nearly a third of total sales — shown by the tallest bar in our Category chart, which suggests marketing spend should keep prioritizing Electronics inventory ahead of the next quarter."

DAX you'll need

Average Order Value = DIVIDE(SUM(Sales[Sales]), DISTINCTCOUNT(Sales[Order ID]))
Before writing any DAX: rename your table to Sales right after loading (right-click the query name → Rename). Every formula on this site assumes that name — a table still called "Sheet1" will show a red error, not because the formula is wrong, but because the name doesn't match.

The one-page cheat sheet

Everything taught in the workshop, condensed.

Golden rule

Always click Transform Data, never Load, unless you've already verified the data is clean.

DIVIDE, not /

DIVIDE() safely handles divide-by-zero. CALCULATE() filters a sum/count by a condition.

DAX formulas from this course

Average Order Value = DIVIDE(SUM(Sales[Sales]), DISTINCTCOUNT(Sales[Order ID])) Profit Margin % = DIVIDE(SUM(Sales[Profit]), SUM(Sales[Sales])) Length of Stay = DATEDIFF(Hospital[Admission Date], Hospital[Discharge Date], DAY) Average Salary = AVERAGE(HR[Salary]) Total Loans = COUNTROWS(Banking) Approved Loans = CALCULATE(COUNTROWS(Banking), Banking[Loan Status] = "Approved") Approval Rate = DIVIDE([Approved Loans], [Total Loans])

10 most common beginner mistakes

  1. Clicking Load instead of Transform Data out of Excel habit
  2. Leaving default chart titles like "Sum of Sales by Category"
  3. Using a Pie Chart with 8+ slices
  4. Forgetting to Trim text columns, silently splitting one customer into two
  5. Summing a column that should be averaged (Salary, Credit Score)
  6. Ignoring outliers instead of investigating them
  7. Using a Bar Chart for a trend over time (should be a Line Chart)
  8. Overloading one page with every chart type "just because you learned it"
  9. Not checking Data Types before building a chart
  10. Skipping Remove Duplicates, quietly inflating every total
