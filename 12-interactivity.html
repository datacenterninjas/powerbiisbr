Module 2 · Interactivity

A dashboard that responds is worth ten that don't.

Every feature on this page turns a static picture into something a viewer can actually explore — click deeper, jump to detail, save a view, tell a story across pages. All of it is on-canvas navigation: nothing here requires leaving Power BI or writing DAX.

Exploring one visual

Drill-down

Concept: Clicking deeper into the SAME on the SAME visual — Category → Sub-Category → Product, one chart, three levels.

Why it matters: One chart answers "what's the total" and "what's inside that total" without building three separate charts.

Real-world example: A retail category manager sees Electronics is the top category, drills in, and finds Laptops are carrying nearly all of it — Headphones barely sell.

Steps

  1. Build a Bar or Column chart with a multi-level field well: drag Category, then Sub Category, into the same Axis well (Power BI treats this as a hierarchy automatically)
  2. Turn on the drill icons in the visual header (the down-arrow and the double-down "expand" icon)
  3. Click a bar, then click the single down-arrow to drill into just that category
  4. Click the up-arrow to drill back up

Try it below — this is a real, clickable mock of the mechanic, not a screenshot:

Category

Click a bar to drill into it. Click "Back" to drill back up — exactly the same up/down motion as the real drill icons.

Common mistake: Putting unrelated fields in the same Axis well and calling it a hierarchy — Region under Product doesn't mean anything; a hierarchy needs a genuine parent-child relationship.

Best practice: Keep hierarchies to 2–3 levels. Beyond that, a drill-through page (below) usually communicates better than a fourth drill level.

Tooltips

Concept: The small popup that appears on hover over a data point, showing extra detail without permanently occupying space on the report.

Why it matters: A chart can only show so many fields before it turns into clutter — a tooltip carries the "nice to know" fields without carrying their visual weight.

Real-world example: A Sales-by-Region map shows just Region and Sales at a glance, but hovering a state reveals Profit Margin and Order Count too.

Steps

  1. Drag any extra field into the Tooltip well of the Visualizations pane
  2. For a richer tooltip, build a separate small report page sized "Tooltip" (Page Information → Tooltip toggle), then reference that page name in another visual's Tooltip well

Best practice: Keep default tooltips to 2–4 fields. Reach for a full report-page tooltip only when hover detail genuinely needs its own mini chart.

Common mistake: Relying on a tooltip to convey a number the audience needs to act on — if it's important enough to decide something, it belongs on the visual itself, not hidden behind a hover.
Drill-down vs. Tooltip: Drill-down changes what the chart is SHOWING (fewer, more specific bars). A tooltip changes nothing on the chart — it only reveals extra detail for the one point being hovered, then disappears.

Jumping to another view

Drill-through

Concept: Right-clicking a data point to jump to a completely separate, filtered detail page built specifically for that context.

Why it matters: Some questions need an entirely different LAYOUT to answer — not just fewer bars on the same chart, but different visuals altogether (a customer's full order history, say).

Real-world example: Right-click a customer on a Sales Overview page, choose "Drill through → Customer Detail," and land on a page built just for that one customer's order history, complaints, and lifetime value.

Steps

  1. Build the detail page (e.g. "Customer Detail")
  2. Drag the field it should filter by (e.g. Customer Name) into the Drill Through well in the Format pane of that page
  3. A "Back" button appears automatically on the detail page
  4. On the source page, right-click any data point → the drill-through page appears under "Drill through"
Common mistake: Forgetting the detail page still needs its own visuals built — drill-through only handles the filtering and navigation, not the page's content.

Try it yourself: Build a one-page "Product Detail" report filtered by Product, drill through to it from a Bar Chart of Sales by Product.

Bookmarks

Concept: A saved snapshot of a report's current state — filters, visibility, selections, even scroll position — that a button can jump straight back to.

Why it matters: It turns a single flexible page into several "views" without duplicating the page, and it's the engine behind interactive storytelling (below).

Real-world example: A dashboard has two bookmarks — "This Year" and "Last Year" — each pre-filtering the same visuals to a different date range, one click apart.

Steps

  1. Set up the report exactly how you want it captured (filters applied, visuals shown/hidden)
  2. View → Bookmarks pane → Add
  3. Name the bookmark clearly (e.g. "This Year")
  4. Repeat for each state you want to save
  5. Wire each one to a button (next lesson)

Best practice: In the bookmark's options, uncheck "Data" if you only want it to control visibility/selection, not re-apply filters — the two behave very differently and it's a common source of confusion.

Buttons & Navigation (Page and Report level)

Concept: Buttons are clickable shapes wired to an action — most often jumping to a bookmark or another page. Navigation is the pattern of using several buttons together as a menu.

Why it matters: A viewer shouldn't need to know Power BI's page tabs exist — a button labeled "Regional Detail" is self-explanatory in a way a small tab strip isn't.

Real-world example: A left-hand strip of buttons — Overview, Sales, Customers, Products — turns a 4-page report into something that feels like a real app.

Steps

  1. Insert → Buttons → Blank (or a built-in style)
  2. Format the button → Action → turn On
  3. Type: Page navigation (jump to a page) or Bookmark (jump to a saved state)
  4. Pick the destination page or bookmark
  5. Repeat for every destination, then duplicate the button strip onto every page for consistent navigation
Common mistake: Hiding the native page tabs (View → Page Navigator off) before every page has its own way back — always leave one path home.
Bookmark vs. Page navigation: Page navigation always jumps to the same fixed page. A bookmark can jump to the SAME page in a different state (different filters, different visuals shown) — or to a different page entirely with a specific state pre-applied. A bookmark is strictly more powerful; a plain page-navigation button is simpler when state doesn't matter.
Tooltip vs. Drill-through: A tooltip stays on the SAME page and disappears the moment the mouse moves away — it's a glance, not a destination. Drill-through actually navigates to a different page that stays put until the viewer clicks Back.

Putting it together

Interactive Storytelling

Concept: Combining bookmarks, buttons, and the Selection pane into a guided sequence — the report walks a viewer through a specific narrative instead of leaving them to find it themselves.

Why it matters: A board presentation needs a story ("here's the problem, here's the driver, here's the recommendation"), not just a dashboard to poke at.

Real-world example: Three bookmarks — "1. The Problem" (a KPI in red), "2. The Driver" (a Bar Chart appears, highlighting one region), "3. The Fix" (a target line and a written recommendation) — stepped through with Next/Back buttons during a live presentation.

Steps

  1. Plan the sequence on paper first: what does the viewer see at each step, and why
  2. Build every visual for every step on the same page (Selection pane will control what's visible when)
  3. Create one bookmark per step, capturing which visuals are visible/hidden at that step
  4. Add Next/Back buttons wired to the bookmarks, or group all bookmarks into a Bookmark navigator (Insert → Buttons → Bookmark navigator) for automatic step buttons

Best practice: Never more than 4–5 steps — storytelling mode is for a live walkthrough, not a replacement for the dashboard someone explores on their own later.
