Choosing the right KPIs — 3-4 numbers, not every number available

The table has ten columns. A dashboard with ten KPI cards communicates nothing — the discipline from the Visualizations page's KPI Card lesson (4–6 cards max) applies here at full strength. Five measures, each with a real business question behind it:

MeasureBusiness question
Total Orders"How many orders came in, full stop — placed, delivered, cancelled, all of it?"
Revenue"How much did we actually earn?" — Cancelled and Refunded orders never became real revenue
Average Order Value"What's the typical order actually worth?"
Cancellation Rate"What share of orders never completed?" — an operations health signal, not a revenue one
Average Rating"Are customers happy with what they got?"
Total Orders = COUNTROWS( FoodDelivery ) Revenue = CALCULATE( SUM( FoodDelivery[Order Value] ), FoodDelivery[Order Status] = "Delivered" ) Delivered Orders = CALCULATE( COUNTROWS( FoodDelivery ), FoodDelivery[Order Status] = "Delivered" ) Average Order Value = DIVIDE( [Revenue], [Delivered Orders] ) Cancellation Rate = DIVIDE( CALCULATE( COUNTROWS( FoodDelivery ), FoodDelivery[Order Status] = "Cancelled" ), [Total Orders] ) Average Rating = AVERAGE( FoodDelivery[Rating] )
Why Revenue and Total Orders deliberately use different row counts: Total Orders counts every row — that's genuinely "how many orders arrived." Revenue and Average Order Value both filter to Order Status = "Delivered" first, because a Cancelled order's Order Value was never actually collected. Building Revenue as a plain SUM(Order Value) with no filter would overstate real revenue by counting money that was never received — exactly the CALCULATE-as-permanent-filter pattern from CALCULATE, FILTER & Modeling, doing real work here instead of a toy example.

Building the five KPI cards

  1. Visualizations pane → Card, drag [Total Orders] into Fields
  2. Repeat for [Revenue], [Average Order Value], [Cancellation Rate], [Average Rating] — five separate Card visuals
  3. Format each: Revenue and Average Order Value → Currency; Cancellation Rate → Percentage; Average Rating → 1 decimal place
  4. Rename each card's title to the plain-English question it answers, not the measure name — "How much did we earn?" reads faster than "Revenue" on a card nobody has time to interpret

Five supporting visuals, each answering one question the KPIs can't

VisualFieldsQuestion it answers
Bar ChartAxis: City · Values: [Revenue], sorted descending"Which city is actually driving the business?"
Pie ChartLegend: Cuisine · Values: [Total Orders]"What are people actually ordering?" (8 cuisines — right at the Rule of 5's edge, worth a second look once real numbers are in)
Line ChartAxis: Order Date (by day or week) · Values: [Revenue]"Is revenue trending up, down, or flat?" — only possible because Order Date is a real Date column now, not the three-format text it started as
Bar Chart + Top N filterAxis: Restaurant · Values: [Revenue] · Filters pane → Top N → 5"Who are our 5 best-performing restaurant partners?" — reuses the Top N skill from Module 2's Filters page
Donut ChartLegend: Order Status · Values: [Total Orders]"What share of orders don't complete?" — 3 values, comfortably inside the Rule of 5, and the one visual that shows Cancelled/Refunded proportion directly instead of hiding it inside the Cancellation Rate card

Laying out one page with intent

Headline numbers go top-left, because that's where a reader's eye lands first — everything else exists to answer the "why" behind those five numbers, not to compete with them for attention.

Top row — the five KPI cards

Left to right, read in under 5 seconds combined: Total Orders, Revenue, Average Order Value, Cancellation Rate, Average Rating.

Below — supporting visuals, largest first

The Line Chart (trend) and City Bar Chart (where) get the most canvas space; the Cuisine Pie, Top 5 Restaurants, and Status Donut share a row underneath as detail a reader digs into only if the headline raises a question.

  1. Apply one Theme to the whole page before placing a single visual — View → Themes
  2. Place the 5 Cards in a single row across the top, equal width
  3. Line Chart and City Bar Chart side by side below, each roughly a third of the remaining height
  4. Cuisine Pie, Top 5 Restaurants Bar, and Status Donut in a row beneath those
  5. Turn on Edit Interactions (Format ribbon) and confirm clicking the City bar chart cross-filters the KPI cards and the other charts — if a card looks like it should react and doesn't, check Edit Interactions for that visual pair specifically

One conditional-formatting touch that earns its place

Cancellation Rate is the one KPI where "higher is worse" — a plain currency-styled card doesn't communicate that. Select the Cancellation Rate card → Format pane → Callout value → Conditional formatting → Font color → a rule where anything over 10% turns the bad-red color, anything under stays the default. One rule, and the single number most likely to need attention now jumps out without anyone reading it as a percentage first.
