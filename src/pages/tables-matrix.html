Module 2 · Tables & Matrix

Sometimes a chart is the wrong answer. Sometimes the audience just wants the numbers.

A Table and a Matrix are Power BI's two grid visuals — no bars, no lines, just rows and columns of exact values. A Table lists rows flat, one per record, the way a spreadsheet does. A Matrix groups rows into a and subtotals automatically, the way a PivotTable does. Same underlying data, two very different shapes — this page builds both from the same Sales rows so the difference is concrete, not theoretical.

Table

Building it: columns, measures & sorting

Concept: A Table visual lists one row per record in your data, with every field you drag in becoming a column — plain columns and DAX sit side by side with no special treatment.

Real-world example: An ops manager wants a literal order log — every Order ID, who bought it, and what it made — to sanity-check the summary charts against, or to export for a follow-up email.

Steps

  1. Visualizations pane → Table
  2. Drag Order ID, Customer, Region, Category, Sub Category into Columns — each adds a plain field, no aggregation
  3. Drag Sales into Columns too — a numeric column defaults to Sum, shown per row here since each row is already one order
  4. Click any column header to sort by it; click again to reverse; a small arrow shows the active sort
  5. Drag column borders in the header to resize, or drag a header left/right to reorder columns
Common mistake: Dropping every available field into a Table "just in case." A Table with 15 columns forces horizontal scrolling and defeats the point — include only what the reader actually needs to check or export.
Formatting: alternating rows, header style & borders

Concept: The Format pane (paint-roller icon) controls how the grid itself looks, separately from the data in it — row banding, header color/font, and gridlines.

Why it matters: A wide table with 20+ rows is hard to scan in a single flat color — the eye loses which row it's on. Small formatting choices carry real readability.

Steps

  1. Format pane → Column headers → set font weight, background fill, and text color
  2. Format pane → Grid → turn on Row banding for alternating row colors, and pick the banded color
  3. Format pane → Grid → set vertical/horizontal gridline weight and color, or turn them off for a cleaner look
  4. Format pane → Values → adjust text size and cell padding once columns feel cramped

Best practice: A subtle row band (a faint tint, not a bright color) does more for scanability than heavy borders ever will — use borders sparingly, mainly to separate the header from the data.

Totals

Concept: A pinned row at the bottom of the table showing one per numeric column — the same idea as an Excel SUM row, built in.

Real-world example: A finance reviewer scrolling a table of 80 orders still needs the grand total of Sales and Profit visible without scrolling back to the top or building a separate KPI card.

Steps

  1. Format pane → Total → toggle on (it's on by default for a new Table)
  2. Still in Total, click each numeric column's dropdown to choose its aggregation — Sum, Average, Count, Min, or Max, set independently per column
  3. Turn the toggle off entirely for a Table meant to be scanned row-by-row, where a totals row would just be noise
Common mistake: Leaving every numeric column defaulted to Sum. Averaging Discount % or Credit Score and summing it instead produces a number nobody can use — check the aggregation per column, not just per table.
Data bars & icons — in-cell visual cues

Concept: Two ways to fold a small chart into a single cell. Data bars shade the cell background proportional to the value, showing relative magnitude without leaving the grid. Icons place a small conditional symbol — commonly an up/flat/down arrow — next to the number based on which rule it matches.

Real-world example: A Sales column with data bars lets a manager spot the biggest orders at a glance, in the same table they're already reading line by line. A Profit column with icons flags which orders lost money with a red down arrow, no separate chart required.

Steps

  1. Select the Table, then in the Format pane find Cell elements
  2. Turn on Data bars, pick the numeric column (e.g. Sales), and set the bar color, minimum, and maximum
  3. Turn on Icons instead (or alongside), pick the column (e.g. Profit), choose an icon set, and set the rule thresholds — e.g. below 0 = red down arrow, above 0 = green up arrow

Best practice: Pick one — data bars or icons — per column, not both; stacking both in the same cell gets visually noisy fast.

Conditional formatting on a Table

Concept: rules can also color a cell's background or font based on its value — the classic red/yellow/green pattern, applied to a whole column at once.

It lives in the same Cell elements panel as data bars and icons above, and the full rule-building walkthrough — background color, font color, rules vs. gradients, applying it to one column vs. the whole table — is its own page next: Conditional Formatting. This page just flags that the option sits here, on a Table exactly like it does on a Matrix.

Search within a table

Concept: A magnifying-glass icon in the visual's header that filters the Table's own rows to whatever text is typed — a live find-as-you-type, scoped to that one visual.

Real-world example: A support rep pulls up the order table during a customer call and types the customer's name to jump straight to their rows, instead of scrolling a hundred-row list.

Steps

  1. Select the Table → Format pane → Header icons → turn on Search
  2. The magnifying-glass icon appears in the visual's top-right corner at report view (not edit view) — click it and type
Common mistake: Confusing this with a report-level — table search only filters that one Table visual, not the rest of the page, and it isn't saved as part of the report's state the way a bookmark or slicer selection is.

Matrix

Rows, Columns & Values wells

Concept: A Matrix has three field wells instead of a Table's one flat Columns well. Rows groups records down the left side — drop more than one field in and it becomes a hierarchy, nested in the order you dropped them. Columns optionally spreads a field across the top instead, turning categories into their own set of columns (a true cross-tab). Values holds the numbers, always aggregated — never one row per record the way a Table shows them.

Real-world example: A regional head wants Sales broken down by Region, then by Category inside each region, as a compact grid rather than one row per individual order.

Field mapping  Table: Sales

Sales[Region] Rows (level 1)
Sales[Category] Rows (level 2, nested)
Sales[Sales] (Sum) Values

All three fields live on the one Sales table — the full worked example is below, under "Table vs. Matrix."

Steps

  1. Visualizations pane → Matrix
  2. Drag Region into Rows
  3. Drag Category into Rows too, underneath Region — Power BI nests it automatically as a second hierarchy level
  4. Drag Sales into Values — it aggregates as Sum by default
  5. Optional: drag a field like Region into Columns instead of Rows to lay Sales across the top as a true cross-tab
Common mistake: Dragging a raw column (not a measure) into Values and expecting it to behave like a Table's per-row column — in a Matrix, every field in Values is aggregated, because Matrix rows represent GROUPS of records, not single records.
Hierarchies & expand/collapse

Concept: Stacking two or more fields in the Rows well (Region, then Category) builds a — Power BI shows a +/- icon next to each Region row so the viewer can open it to see the Categories inside, without those rows always being on screen.

Real-world example: A one-page executive view starts fully collapsed — just four Region rows and their totals. The CFO expands only the region that looks off, instead of scrolling past every Category for every Region up front.

Steps

  1. Click the + icon next to a Region row to reveal just that region's Categories — "expand to next level," one branch at a time
  2. Click the − icon to collapse that branch back
  3. Right-click any row → Expand → Expand entire hierarchy to open every Region's Categories at once, in a single click
  4. Right-click → Collapse → Collapse entire hierarchy to snap everything back down to just the top level

Best practice: Ship a Matrix collapsed to the top level by default (Format pane → Row headers won't remember an expanded state on refresh anyway) — let the viewer choose to drill into what they care about.

Subtotals & Grand totals

Concept: Because a Matrix groups rows, it can show a subtotal at each level of the hierarchy — a Region's total across all its Categories — on top of the single Grand Total across everything, at the very bottom.

Real-world example: Collapsed, a Region/Category Matrix already tells the regional head each region's total Sales — that number is the Region subtotal, visible with zero clicks, before anyone expands anything.

Steps

  1. Format pane → Subtotals → toggle Row subtotals on or off
  2. With multiple row levels, use Per row level to turn subtotals off for just one level (e.g. keep the Region subtotal, drop a redundant Category-only subtotal) while keeping others on
  3. Same panel → toggle Column subtotals if a field is in Columns too
  4. Grand Total is controlled separately in the same Subtotals section
Common mistake: Turning off Grand Total on a report a finance audience will screenshot — losing the one number everyone checks first is a bigger problem than a slightly taller table.
Stepped layout

Concept: With stepped layout on (the default), each nested row level indents further right, so Category rows visually sit "inside" their Region, all sharing one row-header column. Turn it off and every hierarchy level gets its own separate, aligned column instead — Region in one column, Category in the next, side by side.

Real-world example: A dense Matrix with three nested levels (Region → Category → Sub Category) can get visually cramped once stepped — indentation alone stops making the level obvious. Turning stepped layout off gives each level its own labeled column, easier to scan at that depth.

Steps

  1. Select the Matrix → Format pane → Row headers
  2. Toggle Stepped layout off
  3. Adjust Stepped layout indentation instead, if keeping it on but the indent feels too wide or too narrow

Best practice: Keep stepped layout on for 2-level hierarchies — it reads naturally. Consider turning it off once a hierarchy hits 3+ levels, or once viewers keep asking "which column is this indented under?"

Formatting & conditional formatting on a Matrix

Concept: A Matrix takes the same row banding, header style, and gridline options as a Table (Format pane → Grid / Column headers / Row headers), plus its own subtotal/Grand Total styling. — background color, font color, data bars, icons — applies the same way too, in Cell elements, and can be scoped to apply across every level of the hierarchy or only the values shown at one level.

The full conditional formatting workflow — rules, gradients, and the level-scoping option specific to a Matrix — is covered in depth on the next page: Conditional Formatting.

Table vs. Matrix, in one line: A Table shows records. A Matrix shows groups. If the audience needs to see or export individual rows, use a Table. If the audience needs a summary that opens up on demand, use a Matrix.
