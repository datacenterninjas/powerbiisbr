The same formula, a different answer — because of context

The single hardest DAX concept to get comfortable with, and the one that makes everything after it click: a measure has no fixed value — its answer depends entirely on what's currently filtering it.

vs.

Row context

"Which row am I on right now?" — active inside a calculated column (evaluated once per row) and inside iterator functions like SUMX. Covered in depth on DAX Basics & Measures.

Filter context

"What's currently sliced/filtered?" — the region clicked on a map, the year picked on a slicer, even the row a Matrix visual happens to be rendering. A measure re-evaluates fresh inside whatever filter context surrounds it.

This is exactly why a Total Sales measure shows a different number on every row of a Region-by-Category Matrix, and yet is written only ONCE — the formula never changes, only the filter context around it does.

Walking one matrix cell, filter by filter

The fastest way to make filter context concrete: pick one cell, and list out loud every filter that's touching it before looking at the number.

Imagine a Matrix — Rows = DimProduct[ProductLine], Columns = DimProduct[Class], Values = [Total Sales] — sitting on a page with a Region slicer set to "West." Click the cell where the M (Mountain) row crosses the H (High) column. That single cell's [Total Sales] is computed by re-running SUM(FactInternetSales[SalesAmount]) under a filter context built from three separate sources stacked together: ProductLine = "M" (from the row), Class = "H" (from the column), and Region = "West" (from the slicer, invisible on the Matrix itself but still filtering it). Change any one of those three — click a different cell, move the slicer — and the exact same formula recomputes from scratch under the new stack. Nothing about [Total Sales]'s definition ever changes; only what's stacked on top of it does.

Reading context back: SELECTEDVALUE and HASONEVALUE

Once a measure can sense its own filter context, it can report on it — the payoff being a chart title or label that names whatever's currently selected, instead of a generic caption that's technically true for every possible slicer state at once.

Selected Product Line = SELECTEDVALUE(DimProduct[ProductLine], "All Product Lines")

SELECTEDVALUE returns the one value left in context if exactly one remains (a single row clicked, a single slicer value chosen), and falls back to its second argument — here, "All Product Lines" — the moment more than one value is in play. That fallback is doing real work: without it, a multi-selection returns blank, not an error, and a dynamic title that goes silently blank is worse than a wrong one, because nothing on screen tells you it broke.

Same idea, boolean form: HASONEVALUE(DimProduct[ProductLine]) returns TRUE only when filter context has narrowed that column to exactly one value — useful inside an IF when a measure needs to behave differently at a summary level (multiple values in context) than it does drilled all the way down to one.

Dynamic measures with IF

Wrapping a measure in IF lets it change WHAT it calculates based on a condition, not just format the same number differently.

Status Flag = IF([Total Sales] > [Target], "On Track", "Behind")
The outcome to check for yourself: can you point at any single number in any visual on a page you've built and say, out loud, every filter responsible for it? If yes, everything from here through CALCULATE, FILTER & Modeling is just naming and controlling what you can already see.
