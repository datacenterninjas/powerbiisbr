SQL Server & AdventureWorks

A closer look at connecting Power BI to a real SQL Server database, using Microsoft's AdventureWorks sample database as the running example — the same "Connecting to SQL Server" basics from earlier, applied end-to-end against a real multi-table database instead of a single Excel file.

The connection walkthrough itself is still being built out as the class gets here. Downloading and installing the database, below, is ready now — the click-paths, screenshots, and sample queries for actually connecting Power BI to it will land here session by session.

Where to download it

AdventureWorks is Microsoft's own free sample database, published on GitHub under microsoft/sql-server-samples, inside samples/databases/adventure-works. It ships in three variants — use AdventureWorksDW, the data-warehouse version, to match every AdventureWorks example already on this site (Visualizations page, etc.):

VariantWhat it isUse for this course?
AdventureWorksDWPre-built star schema — fact tables (FactInternetSales, FactResellerSales) plus dimension tables (DimProduct, DimCustomer, DimDate, DimGeography…)Yes — this is the one
AdventureWorks (OLTP)Full normalized transactional database, dozens of tables across 5 schemasOptional — an "advanced/realistic" detour once the star schema feels comfortable
AdventureWorksLT"Light" — a small simplified subsetOnly if DW feels like too much at first
github.com→microsoft/sql-server-samples→samples/databases/adventure-works→pick your SQL Server version→download the .bak file

Grab the AdventureWorksDW20XX.bak file matching your SQL Server version (2016 through 2022 are all listed) — a .bak is a database backup file, the standard format SQL Server restores from directly. It's a few hundred MB; give it a minute to download.

Free to use: AdventureWorks is released by Microsoft under the MIT license — safe to download, install, and reuse for classroom teaching with no licensing cost or restriction.

How to install it (restore the .bak)

Restoring is how you turn a downloaded backup file into a real, queryable database on your SQL Server instance.

  1. Open SQL Server Management Studio (SSMS) and connect to your local or class SQL Server instance
  2. In Object Explorer, right-click Databases → Restore Database…
  3. Choose Device as the source → click the … button → Add → browse to the downloaded AdventureWorksDW20XX.bak
  4. Under Files (left-hand page of the dialog), confirm the destination file paths look reasonable — SSMS usually gets this right automatically
  5. Click OK to start the restore — a few hundred MB typically takes under a minute on a normal laptop
  6. Verify it worked: expand Databases → AdventureWorksDW20XX → Tables and confirm you can see FactInternetSales and DimProduct in the list

No SSMS installed?

SSMS is a free download from Microsoft, Windows-only. On Mac/Linux, Azure Data Studio (also free, cross-platform) has an equivalent Restore flow under its Servers/Connections pane.

No local SQL Server?

SQL Server Developer Edition is free for non-production use, or run SQL Server in a Docker container — either way, restore the same .bak file once the instance is up.

Common mistake: Downloading the OLTP AdventureWorks20XX.bak by accident instead of AdventureWorksDW20XX.bak — the file names are one letter apart and sit right next to each other on the releases page. Double-check the filename contains "DW" before restoring.

A note on how this stays a static site

This page is reference material, not a live connection — GitHub Pages only serves static files, so it can't reach into a private SQL Server the way Power BI Desktop on your own machine can. What lands here is the same kind of content as the rest of the course: click-paths, screenshots, and sample queries to follow along with in your own Power BI Desktop.
