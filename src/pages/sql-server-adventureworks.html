SQL Server & AdventureWorks

A closer look at connecting Power BI to a real SQL Server database, using Microsoft's AdventureWorks sample database as the running example — the same "Connecting to SQL Server" basics from earlier, applied end-to-end against a real multi-table database instead of a single Excel file.

This module is being built out as the class gets here. The page is live and linked from the sidebar now so it has a permanent home — click-paths, screenshots, and sample queries against AdventureWorks will land here session by session.

What this module will cover

  • 1
    Getting AdventureWorks running. Restoring the sample database (or connecting to a shared class instance) so everyone is querying the same data.
  • 2
    Get Data → SQL Server, for real. Server name, database name, and authentication against an actual multi-table database instead of a single Excel file.
  • 3
    Import vs. DirectQuery, revisited. Why the choice matters more once the source is a real database that many people query at once.
  • 4
    Modeling AdventureWorks' relationships. A real star-schema-shaped set of tables — Sales, Products, Customers — instead of the single flat tables used earlier in the course.

A note on how this stays a static site

This page is reference material, not a live connection — GitHub Pages only serves static files, so it can't reach into a private SQL Server the way Power BI Desktop on your own machine can. What lands here is the same kind of content as the rest of the course: click-paths, screenshots, and sample queries to follow along with in your own Power BI Desktop.
