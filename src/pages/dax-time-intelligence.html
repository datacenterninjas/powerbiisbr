Time intelligence functions and functions are the two DAX building blocks you'll reach for most often, in almost every real report.

Two tables, one line — the single exception to "no joins"

Every worked example on this site up to now has deliberately stayed on one table. Time intelligence is the one place that rule bends: TOTALYTD and SAMEPERIODLASTYEAR need a proper — DimDate, related to FactInternetSales — and there's no honest single-table version of that. This is the one relationship this course asks you to build before Module 3 is done, and it's exactly one line.

  1. Model view (left rail) → confirm a line connects FactInternetSales[OrderDateKey] to DimDate[DateKey] — Power BI usually autodetects this; if it didn't, drag one column onto the other
  2. Click DimDate → Table tools ribbon → Mark as Date Table → point it at DimDate[FullDateAlternateKey] (a real, continuous datetime column — not the integer DateKey)

That's the whole exception. Full data modeling — several fact tables, role-playing dimensions, a star schema built from scratch — is deliberately out of scope for this course (it's Extended Module 09, not yet built); this one relationship is as far as Module 3 needs to go.

Time intelligence — the same measure, a different time window

YTD (Year-to-Date) answers "total so far, within the current period" — without hand-typing a date range that goes stale the moment the calendar turns over.

Sales YTD = TOTALYTD ( [Total Sales], DimDate[FullDateAlternateKey] )
Why this needs a real Date table: the same "Date column typed as text sorts wrong" trap already covered on the Power Query and Visualizations pages resurfaces here, with higher stakes — TOTALYTD doesn't just sort wrong on an untyped or unmarked date column, it silently returns the wrong total or errors outright.

Prior-period comparisons: the "vs. last year" card every executive dashboard has

Sales LY = CALCULATE ( [Total Sales], SAMEPERIODLASTYEAR ( DimDate[FullDateAlternateKey] ) ) YoY Growth % = DIVIDE ( [Total Sales] - [Sales LY], [Sales LY] )

Sales LY is a soft first look at CALCULATE — used here before it's formally explained, as "the function that changes what a measure looks at." CALCULATE, FILTER & Modeling opens the hood on exactly what it's doing and re-derives this same formula once you can read it properly.

Rolling averages, the same tool doing a third job

Sales Rolling 3M = CALCULATE ( [Total Sales], DATESINPERIOD ( DimDate[FullDateAlternateKey], MAX ( DimDate[FullDateAlternateKey] ), -3, MONTH ) )

DATESINPERIOD hands CALCULATE a rolling 3-month date window ending at whatever date is currently in context — smooths a noisy monthly line into a trend without deleting a single row of the underlying detail.

Practice: the AdventureWorksDW-only Tier B problems on DAX Practice are built entirely from this page — the inbuilt CSV datasets only span one calendar year each, not enough history for a genuine year-over-year comparison, so time-intelligence practice stays on AdventureWorksDW here rather than pretending otherwise with a take-away CSV twin.
