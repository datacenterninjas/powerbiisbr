⭐ Combination DAX Patterns Spotlight

DAX gains its real power when functions are chained together. In enterprise models, a single function rarely solves a business requirement alone — combinations alter filter context, iterate across relationships, and handle dynamic executive logic.

Core Pattern #1

CALCULATE + FILTER

When required: A bare CALCULATE(..., Sales > 1000) only accepts simple single-column constant filters. You must combine with FILTER() whenever: (1) you compare two columns to each other, (2) you reference a measure inside the condition, or (3) you apply multi-column row logic.

// Filtering by measure or dynamic row logic High Profit Sales = CALCULATE( [Total Sales], FILTER( DimProduct, DimProduct[ListPrice] > DimProduct[StandardCost] * 2 ) )

FILTER(DimProduct, ...) returns a filtered table that CALCULATE applies as its new filter context.

Core Pattern #2

CALCULATE + ALL

When required: Market share, % of category, or benchmark ratios where the denominator must ignore whatever slicers or visual rows are currently filtering the data.

// Market Share / % of Grand Total % of All Sales = DIVIDE( [Total Sales], CALCULATE( [Total Sales], ALL( FactInternetSales ) ), 0 )

ALL removes all filters from the table or column, providing a fixed grand total denominator.

Core Pattern #3

CALCULATE + ALLSELECTED

When required: Percentage of user selection. Unlike ALL (which ignores even the user's slicers), ALLSELECTED respects external page slicers while clearing the visual's internal row/column axes.

// Respects Category slicer, but sums across table rows % of Filtered Selection = DIVIDE( [Total Sales], CALCULATE( [Total Sales], ALLSELECTED( DimProduct ) ), 0 )

If the user filters to "Bikes", the rows sum to 100% of Bikes rather than % of all company sales.

Core Pattern #4

CALCULATE + ALLEXCEPT

When required: Category subtotals. Strips filters from every column on a dimension except the specified column(s). Great for "Product sales as % of its Parent Category."

// Keeps Category filter, strips Subcategory and Product filters Category Total Sales = CALCULATE( [Total Sales], ALLEXCEPT( DimProduct, DimProduct[ProductLine] ) )

Calculates the total for Road Bikes across all individual bike models in that line.

Core Pattern #5

CALCULATE + USERELATIONSHIP

When required: Role-playing dimensions. When a fact table has multiple dates (Order Date, Ship Date, Due Date), Power BI only allows one active relationship. USERELATIONSHIP activates the inactive relationship inside that measure.

// Analyzes sales by Ship Date instead of default Order Date Sales by Ship Date = CALCULATE( [Total Sales], USERELATIONSHIP( FactInternetSales[ShipDateKey], DimDate[DateKey] ) )

Enables plotting both Order Date volume and Shipping Date volume on the same calendar axis.

Core Pattern #6

CALCULATE + KEEPFILTERS

When required: By default, CALCULATE overrides existing filters on the same column. Wrapping the filter in KEEPFILTERS tells DAX to intersect instead of override.

// Intersects with slicer; returns blank if slicer is set to "Mountain" Safe Road Bike Sales = CALCULATE( [Total Sales], KEEPFILTERS( DimProduct[ProductLine] = "R" ) )

Prevents accidental display of Road Bike sales when an executive specifically filtered to Mountain Bikes.

Core Pattern #7

SUMX + RELATED

When required: Multiplying a transaction quantity on the Fact table (Many side) by a unit cost or price sitting in a Dimension table (One side).

// Evaluated row by row on Fact, fetching Unit Price from DimProduct Total Revenue at List Price = SUMX( FactInternetSales, FactInternetSales[OrderQuantity] * RELATED( DimProduct[ListPrice] ) )

RELATED traverses the 1-to-many relationship inside the row context created by SUMX.

Core Pattern #8

SWITCH + TRUE()

When required: Multi-condition decision ladders, performance scoring, or custom text tagging. Replaces messy nested IF() statements.

// Executive Performance Classification Ladder Performance Tier = VAR MarginRate = [Profit Margin %] RETURN SWITCH( TRUE(), MarginRate >= 0.40, "Tier 1: High Margin (40%+)", MarginRate >= 0.20, "Tier 2: Standard (20-39%)", MarginRate > 0, "Tier 3: Low Margin (<20%)", "Tier 4: Loss Making" )

Evaluates conditions in sequential top-down order until the first true expression is found.

Core Pattern #9

CONCATENATEX + VALUES

When required: Dynamic titles, card subtitles, or tooltips that list all items currently chosen in a multi-select slicer.

// Returns "Selected Cities: Bangalore, Mumbai, Delhi" Selected Regions List = VAR SelectedList = CONCATENATEX( VALUES( DimSalesTerritory[SalesTerritoryRegion] ), DimSalesTerritory[SalesTerritoryRegion], ", ", DimSalesTerritory[SalesTerritoryRegion], ASC ) RETURN "Regions: " & SelectedList

Turns tabular filter context into a clean, comma-delimited string for card visuals or chart headers.

Core Pattern #10

ADDCOLUMNS + SUMMARIZE

When required: The recommended best practice for generating virtual tables. Never compute measures directly inside SUMMARIZE (which can cause severe performance bugs); use ADDCOLUMNS wrapped around SUMMARIZE.

// Golden pattern for virtual table aggregations Average Customer Sales = VAR CustomerTable = ADDCOLUMNS( SUMMARIZE( FactInternetSales, FactInternetSales[CustomerKey] ), "@CustSales", [Total Sales] ) RETURN AVERAGEX( CustomerTable, [@CustSales] )

Summarizes unique customers, calculates sales per customer with context transition, then averages them.
