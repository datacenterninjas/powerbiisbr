Joins and Merge Queries in Power Query

In enterprise analytics, data rarely lives in a single pristine table. When you need to enrich transactions with customer profiles, attach return reasons to sales, or audit unmatched inventory, Merge Queries is your primary tool in Power Query. This guide covers all six join types, composite keys, fuzzy matching, self-joins, and performance best practices.

Files for this guide: PQ_Practice_Orders.csv (35 rows) and PQ_Practice_Returns.csv (10 rows). Download both and open them via Get Data → Text/CSV → Transform Data.

Merge Queries vs. Merge Queries as New

When you click the Merge button on the Home ribbon, Power Query gives you two choices:

Merge Queries (In-Place)

Alters the Active Query

Adds the merged column directly into the query you currently have selected. Use this when enriching an established fact or dimension table (e.g., adding Return Reason straight into your existing Orders table).

Merge Queries as New

Creates a New Query

Leaves both original source tables completely untouched and outputs a brand-new third query. Best practice when merging raw staging queries where you want to keep raw sources intact, unchecking Enable load on the parents.

Left Outer
All from 1st, matching from 2nd		 Keeps every row from the top table. Where a match exists, pulls data from the second table; otherwise leaves null. 35 Enriching an orders table with return reasons or customer demographics without dropping unreturned orders.

Expand vs. Aggregate: Unpacking the Merged Column

Once the merge finishes, Power Query inserts a new column containing Table objects. Click the two-way arrow icon (⇄) in the column header to choose your extraction method:

Expand Option

Pulls in Specific Columns

Brings individual column values into your table row by row (e.g., Return Reason, Refund Amount). Always uncheck "Use original column name as prefix" to avoid clumsy headers like Returns.Return Reason.

Aggregate Option

Computes Summaries Directly

Instead of adding detail rows, calculates an immediate aggregate (e.g., Count of Returns, Sum of Refund Amount). Ideal when joining a 1-to-many relationship where you want one summary number per order without multiplying rows.

Advanced Joins in Power Query

1. Composite Key Merging (Multi-Column Matching)

Often a single column is not unique. For instance, in manufacturing or retail order lines, an order number repeats for every line item. To join on a composite key:

  1. Select the primary table in the top pane. Click Order ID, then hold Ctrl and click Line Number. Power Query numbers them 1 and 2.
  2. In the bottom pane, click Order ID, then hold Ctrl and click Line Number in the exact same sequence.
  3. Power Query matches rows only where both column values match simultaneously.

2. Fuzzy Matching (Handling Real-World Typos)

Exact matching fails on real dirty strings like "Bengaluru" vs. "Bangalore" or "Microsoft Corp." vs. "Microsoft". In the Merge dialog, expand Fuzzy matching options:

OptionWhat it doesRecommended Setting
Similarity thresholdScore from 0.00 to 1.00 determining how closely text must match. (1.00 is exact match).0.80 (default). Going below 0.70 produces false positives (e.g., matching "Robert" with "Albert").
Ignore caseMatches uppercase, lowercase, and mixed case automatically.Always checked.
Match by combining text partsMatches strings like "Micro Soft" with "Microsoft".Check for company names and addresses.
Transformation tableA reference query mapping synonyms (e.g., From: "MSFT" → To: "Microsoft").Use for standard corporate abbreviation tables.

3. Self-Joins (Parent-Child Hierarchies)

To look up an employee's manager name when both employee and manager records sit in the same HR table:

Select HR Table→Merge Queries→Top: HR (Manager ID)→Bottom: HR (Employee ID)→Left Outer→Expand Manager Name

This places each employee's direct supervisor's name directly onto their row in a single step.

Four Dangerous Merge Traps to Avoid

Trap #1: Row Multiplication

Cartesian Explosion

If the lookup key in Table 2 contains duplicates, a Left Outer join creates a row for every match. 49 orders can balloon into 98 rows, doubling your revenue. Fix: Deduplicate the lookup table before merging.

Trap #2: Type Incompatibilities

Number vs. Text Mismatch

If Order ID is Whole Number in Table 1 but Text in Table 2, the merge produces 0 matches with zero warning. Fix: Check type icons (123 vs ABC) on both key columns.

Trap #3: Trailing Whitespace

Invisible Spaces

Power Query matches strings with exact byte equality: "ORD101 " will never match "ORD101". Fix: Run Transform → Format → Trim on both key columns prior to merging.

Trap #4: Broken Query Folding

Local Buffering Overload

Merging a SQL database table with an Excel sheet breaks query folding, forcing Power BI to download the entire SQL table into memory. Fix: Filter SQL tables before merging across mixed sources.

Check Yourself

What is the difference between Left Anti and Right Anti joins?

Left Anti keeps only the rows from the first (top) table that have no match in the second. Right Anti keeps only rows from the second (bottom) table that have no match in the first. Right Anti is particularly valuable as a data-quality audit check for identifying orphan records in reference tables.

Why should you uncheck "Enable Load" on staging tables after merging them?

When you merge Table A and Table B into Table C, keeping Table A and Table B loaded in Power BI wastes RAM in the VertiPaq memory engine and clutters the report canvas Fields pane. Unchecking "Enable Load" keeps them purely as background transformations feeding Table C.

How do you merge two tables based on both Year and Month?

Use a composite key merge: in the Merge Queries dialog, click Year, then hold Ctrl and click Month in Table 1. Repeat the exact same sequence in Table 2. Power Query labels the selections 1 and 2 and matches on both fields simultaneously.
