CALCULATE: the one function that changes everything else

CALCULATE is the function that lets a measure override its own filter context on purpose — arguably the single most important function in all of DAX.

This page is a placeholder — full lesson content lands here as the class reaches this module. The framing below is real; the guided walkthrough, exercises, and quiz questions are still to come.

CALCULATE and FILTER

Electronics Sales = CALCULATE( SUM(Sales[Sales]), Sales[Category] = "Electronics" )

Read this as: "Compute SUM(Sales[Sales]), but first override the filter context so only Category = Electronics rows count — regardless of what the report's own slicers currently say." That override is the entire trick, and everything from "Approval Rate" on the Cheat Sheet page to a proper YTD calculation is built on it.

Every DAX example already on this site that uses CALCULATE — Approved Loans, Length of Stay comparisons — is doing exactly this: computing a number under a DELIBERATELY different condition than whatever's currently on screen.

Relationships and data modeling best practices

None of the above works without a correctly built between tables — the same Data Model concept from the Architecture page, revisited with the modeling discipline a real project needs.

, not a web

One central fact table, dimension tables branching off it — never dimension-to-dimension relationships if a fact table can sit between them instead.

matters

Relationships should run from the "many" side (a fact table, many rows per customer) to the "one" side (a dimension table, one row per customer) — get this backwards and totals silently multiply.
