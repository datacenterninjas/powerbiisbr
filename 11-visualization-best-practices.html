Module 2 · Best Practices

The chart is right. Now make it honest, clean, and readable in three seconds.

Picking the correct chart type is half the job — the Visualizations page's "Which chart, when?" table already covers that. This page is the other half: the cross-cutting formatting and design discipline that decides whether a technically-correct chart tells the truth clearly, or quietly misleads, clutters, or gets ignored. Every rule here applies no matter which of the twelve chart types you picked.

Choosing the chart itself — business question → chart type, plus per-chart best practices and common mistakes — lives on the Visualizations page's "Which chart, when?" table. This page assumes the chart type is already decided and focuses only on how it's formatted and presented.

Avoiding misleading charts

A chart can use the "right" type and still lie. None of the tricks below require bad intent — they're often just Power BI's defaults left un-fixed — but the effect on a reader is the same either way: a false impression of how big a difference really is.

TrickWhat it doesFix
Truncated / non-zero Y-axisStarting the axis at 90 instead of 0 turns a 4% difference into what looks like a 400% differenceFormat pane → Y-axis → Range → set Minimum to 0, unless there's a genuinely documented reason not to
Inconsistent scales between compared chartsTwo bar charts placed side by side, one axis maxing at 100 and the other at 1,000 — bars look similar height but represent wildly different valuesLock both visuals to the same axis Minimum/Maximum in the Format pane before placing them side by side
Cherry-picked date rangeZooming into the three months that support the story and quietly dropping the ones that don'tDefault every trend to the full available history; let a viewer narrow the range themselves with a slicer, don't narrow it for them
Dual axes implying false correlationTwo unrelated measures plotted on independent left/right axes can be dragged into looking like they move together, when the scales were just picked to make the lines crossOnly combine two measures on dual axes when they share a real, meaningful relationship — and say so in the title

Same underlying numbers, two very different impressions — this is the single most common way a Power BI report misleads without anyone intending to:

Needs improvement · axis starts at 80

Region C looks nearly 3× Region A — but the axis is truncated, so the visual gap is exaggerated far past the real difference.

exaggerates the gap
Good · zero-based axis

Same three regions, same underlying numbers, axis starts at 0 — Region C is ahead, but honestly by a modest margin, not a landslide.

reads honestly
Common mistake: Power BI's default axis is usually zero-based, but "Auto" range on some visuals will truncate automatically once values cluster in a narrow band. Always check the Format pane's Range setting explicitly — don't assume the default protected you.

Appropriate use of color

Color is the fastest channel a viewer's eye reads — which is exactly why it needs the most discipline. Used well, it points straight at what matters. Used as decoration, it competes with the data for attention and usually wins.

Do

  • ✓
    Pick one consistent palette for the whole report (Format pane → Theme) and stop touching it per-visual
  • ✓
    Let color mean something — the same category is always the same color across every page
  • ✓
    Choose a colorblind-safe palette (avoid pure red/green as the only distinguishing pair — roughly 1 in 12 men has some form of red-green color blindness)
  • ✓
    Use color sparingly, to highlight — one accent color on the bar that matters, neutral gray everywhere else

Don't

  • ✕
    Give every category its own rainbow color just because the Legend well auto-generates one
  • ✕
    Let a category's color drift between pages — Electronics blue on page 1, Electronics green on page 3
  • ✕
    Rely on red vs. green alone to signal good vs. bad — pair it with an icon, label, or shape too
  • ✕
    Color a chart just because a blank white bar "looks unfinished" — color without meaning is noise

The same five categories, formatted two ways:

Needs improvement · color as decoration

A different color per bar for no reason — the eye tries to find meaning in the color choice and finds none.

competes with the data
Good · one accent, used to highlight

Neutral teal for every bar, one accent color on the single bar that's the point of the chart — the eye lands there first.

points at the insight

Consistent formatting across a report

A report that switches fonts, number formats, or color schemes between pages reads as unfinished even when every number on it is correct — inconsistency is itself a signal that erodes trust before anyone checks the data.

One theme

View → Themes → pick or build one custom theme, apply it once, and stop hand-picking colors per visual afterward.

One font

Set it in the theme, not visual-by-visual — a report mixing Segoe UI titles with Calibri axis labels looks assembled from spare parts.

One number format

Decide once whether currency is ₹, $, or unlabeled, how many decimal places, and apply that same rule to every measure on every page.

Titles and labels

Power BI's auto-generated title — "Sum of Sales by Category" — describes the mechanics of the chart, not what it tells you. A real title does the reader's first thinking step for them.

Needs improvement

"Sum of SalesAmount by Region"

Restates the field names. Says nothing a viewer couldn't already see in the Fields pane.

Good

"West leads every other region by 2×"

States the finding directly. A viewer who reads only the title still walks away informed.

Axis and legend labels deserve the same attention: rename a field-derived label like "SUM(Sales_Amt)" to plain "Sales ($)" in the Format pane before a report ever leaves your laptop.

Data labels

A data label prints the exact number directly on the chart — genuinely useful when there are few enough data points to read cleanly, actively harmful once there are too many.

Chart is…Data labelsWhy
A KPI Card, Gauge, or a Bar Chart with ≤ 8–10 barsturn onFew enough points that the exact number adds precision without crowding
A dense Line Chart (daily data across a year) or a Scatter Plot with 100+ pointsleave offLabels overlap into an unreadable smear — let the shape of the line or cluster carry the message, use a tooltip for exact values on hover
A Pie Charton, as % of totalA pie only works if the reader can see the actual share each slice represents, not just relative size

Number formatting

  • ✓
    Display units: Format pane → Display units → Thousands/Millions turns "1,240,000" into a much faster-to-read "1.24M"
  • ✓
    Consistent decimal places: pick one rule (e.g. currency to 0 decimals, percentages to 1) and apply it to every measure of that type, everywhere in the report
  • ✓
    Currency symbols: set once in the measure's format string, not retyped as text in a title — a hardcoded "$" breaks the moment the report is reused for a different currency

Sorting

Bars sorted biggest-to-smallest let a reader find the winner and the laggard in one glance, without hunting across the chart. That's the default for anything without an inherent order.

The one exception: when categories have a natural order of their own — months of the year, days of the week, a funnel's stages — keep that natural order instead of re-sorting by value. Forcing "Jan, Jun, Mar, Dec…" into value order destroys the thing a time axis is supposed to communicate.

Reducing clutter

Every gridline, border, and legend a Power BI default turns on is a small tax on the reader's attention. If it isn't earning its place, it's competing with the data that is.

ElementUsuallyKeep it when…
GridlinesTurn off or lighten (Format pane → Gridlines)The chart genuinely needs precise value reading, not just shape comparison
Visual borderTurn off — let a card's background do the separatingRarely — borders mostly just add visual weight
LegendTurn off when there's only one series, or when data labels already name each barMultiple series/colors that genuinely need a key to decode
Axis titleOften removable if the chart title already makes the axis obviousThe unit isn't otherwise clear from the chart title or labels
Common mistake: Formatting a chart once and never revisiting it. After data labels, a title, and units are all on, go back and turn off anything that no longer earns its place — most reports get cluttered by addition, never by a single bad decision.

Accessibility

  • ✓
    Contrast: text and important marks should be clearly readable against their background — Power BI's built-in themes are checked for this; a fully custom palette should be too
  • ✓
    Never color alone: pair red/green status with an icon, label, or pattern, so the meaning still lands for a colorblind viewer or a black-and-white printout
  • ✓
    Alt text: Format pane → General → Alt text — a short description of what the visual shows, read aloud by screen readers

Mobile and responsive considerations

A report built and tested only on a wide desktop monitor can be genuinely unusable on the phone where a manager actually opens it between meetings.

View→Phone layout→drag visuals into a single-column stack→reorder so the most critical visual is at the top

Power BI keeps a separate phone layout from the desktop one — building it isn't automatic. The KPI or single chart someone needs first (this month's headline number, say) belongs at the very top of that stack; everything a viewer might scroll past should be exploratory detail, not the answer to the question they opened the report to ask.

Avoiding unnecessary 3D effects

3D is flatly worse for reading data accurately — a 3D pie or column chart distorts the visual size of the slice or bar closest to the "camera," making it look larger than its actual value while the far side looks smaller. There is no business scenario on this course's data where a 3D effect adds real information; it only adds a perception error. Stick to flat 2D charts.

Highlighting important insights

A dashboard that presents forty numbers with equal visual weight makes the reader do the work of finding the one that matters. Do that work for them.

A callout box

A text box or the built-in Report Page Tooltip pattern that states the one-sentence takeaway in plain language, placed near the chart it explains — not buried in a title.

Conditional highlight color

One bar (or one row, via ) in the accent color while the rest stay neutral — the same technique used in the color mockup above.

Keeping dashboards focused

A page built to answer "how did we do this quarter" and a page built to answer "which customers are at risk of churning" are two different pages, even if they'd both technically fit on one. One clear purpose per page beats a single page trying to be everything the company owns data about.

Common mistake: "Let's just add it to the main dashboard" as the default answer to every new stakeholder request. A page that tries to answer every question ends up answering none of them clearly — a focused page a viewer understands in ten seconds is worth more than a comprehensive one they give up on.

Matching visual complexity to the audience

AudienceWantsReport shape
An executiveThree numbers and a trend, in under 10 secondsA handful of KPI cards plus one trend line — headline page first, everything else behind a click
An analystThe full table, ability to slice and drillA Matrix/Table with slicers, drill-down enabled, and a Tooltip well carrying extra detail
Anyone, on their phone, between meetingsThe single number they came to checkPhone layout with that number pinned at the top (see Mobile, above)

The same underlying model can serve both — an executive summary page built from cards and a KPI trend, and a detail page built from a full Matrix, linked by a button (see Interactivity). Building one page and hoping it satisfies both audiences is how a report ends up too sparse for the analyst and too dense for the executive at the same time.

The one-line test: before shipping any report, ask whether a first-time viewer — someone who has never seen this data before — could look at each chart for five seconds and correctly state what it's telling them. If not, the fix is almost always on this page: a truncated axis, a missing title, decorative color, or clutter that needs removing.
