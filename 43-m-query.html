M: the language behind every click

Every Applied Step you've made is a line of M code. This page teaches you to read that code, fix it when a step breaks, and write it when no button does what you need. It ends with a whole query written by hand. The next page then applies these skills to a complete ETL pipeline.

Set-up: this page continues the AllOrders query from Joins & Data Modelling (Orders + Orders_Feb appended, duplicates removed, 49 rows). Only have PQ_Practice_Orders.csv? Most examples still work on it; only the row counts differ.

Anatomy of a query

Open PQ_Practice_Orders.csv fresh, trim First Name, and open the Advanced Editor. You'll see something like this (your file path will differ):

let Source = Csv.Document(File.Contents("C:\Data\PQ_Practice_Orders.csv"), [Delimiter = ",", Columns = 14, Encoding = 65001, QuoteStyle = QuoteStyle.Csv]), #"Promoted Headers" = Table.PromoteHeaders(Source, [PromoteAllScalars = true]), #"Changed Type" = Table.TransformColumnTypes(#"Promoted Headers", {{"Order ID", type text}, {"Unit Price", type number}, /* …one pair per column… */}), #"Trimmed Text" = Table.TransformColumns(#"Changed Type", {{"First Name", Text.Trim, type text}}) in #"Trimmed Text"
  1. let opens a list of named steps. in says which step is the query's output, almost always the last one
  2. Each step is Name = expression, and steps are separated by commas. The last step before in has no comma
  3. Each step takes the previous step's name as its input. #"Trimmed Text" starts from #"Changed Type". That chain of names is the Applied Steps pane
  4. #"…" quotes a name that contains spaces or symbols. Source needs no quoting; #"Promoted Headers" does
  5. {…} is a list and […] is a record. {{"First Name", Text.Trim, type text}} is a list of one list: "for column First Name, apply Text.Trim, and the result is text"
Why the chain matters: steps don't have to follow each other in order. Any step can reference any earlier step by name, and that's how you'd go back to Source to compare. But the UI assumes a straight chain, so keep it one when you edit by hand.

each and _: the shorthand in every generated step

each means "a small function, applied to each item". _ is the item. What the item is depends on the function that receives it:

StepWhat _ isExample
Table.SelectRows, Table.AddColumnThe whole row (a record). [Qty] is short for _[Qty]Table.SelectRows(AllOrders, each [Qty] > 2)
Table.TransformColumnsOne cell's value{"Channel", each Text.Proper(_)}
Table.Group aggregationsThe sub-table of rows in the groupeach Table.RowCount(_)

each [Qty] > 2 is exactly the same as (_) => _[Qty] > 2, a function with one parameter named _. You'll write the long form when a function needs more than one input (see Custom functions below).

Decisions: if, try, and blanks

// if … then … else — the else is NOT optional in M = if [Discount %] >= 10 then "Promo" else "Full price" // chain conditions with else if = if [Unit Price] >= 2000 then "Premium" else if [Unit Price] >= 800 then "Mid" else "Entry" // try … otherwise — catch a conversion that fails ("N/A" on ORD2011) = try Number.From([Qty]) otherwise null // ?? — "use the right side if the left side is null" (ORD2017's blank Discount %, once the column is typed) = [Discount %] ?? 0
try … otherwise hides problems as easily as it solves them. Use it where you've decided what a failure means ("N/A" quantity = unknown = null). Don't wrap a whole step in it to make a red error go away. A silent null in a revenue column is worse than a visible error.

Forgot a function's arguments? Type its name alone as a step (= Text.BeforeDelimiter, no brackets) and Power Query shows its documentation, with a form to try it.

Replacer.ReplaceValue vs Replacer.ReplaceText: the first replaces a cell only if the whole value matches. The second replaces text inside a value. Replacing "Onlin" with "Online" using ReplaceText would also turn every correct "Online" into "Onlinee". The UI picks ReplaceValue when you tick Match entire cell contents.

Reading what the UI wrote

Merge (from Joins & Data Modelling) is two steps: the join, then the expand.

#"Merged Queries" = Table.NestedJoin(AllOrders, {"Order ID"}, Returns, {"Order ID"}, "Returns", JoinKind.LeftOuter), #"Expanded Returns" = Table.ExpandTableColumn(#"Merged Queries", "Returns", {"Return Reason", "Refund Amount"}, {"Return Reason", "Refund Amount"})

Arguments, in order: left table, left key(s) as a list, right table, right key(s), the name of the new nested column, the join kind. Changing join kind is a one-word edit: JoinKind.Inner, LeftAnti, RightAnti, RightOuter or FullOuter. Swap it in the formula bar and watch the row count move through the numbers from the joins page.

Unpivot on PQ_Practice_Wide.csv (5 regions × 4 month columns):

#"Unpivoted" = Table.UnpivotOtherColumns(#"Changed Type", {"Region"}, "Attribute", "Value"), #"Renamed" = Table.RenameColumns(#"Unpivoted", {{"Attribute", "Month"}, {"Value", "Sales"}})

5 rows × 4 months become 20 rows of Region / Month / Sales. The second argument lists the columns to keep, which is why "Unpivot Other Columns" is the safe choice: when a May column arrives next month, it's unpivoted automatically, because it isn't in the keep list.

Write a whole query by hand

The question: completed revenue by channel, net of discount, from AllOrders, with every data problem handled in code. Home → New Source → Blank Query → Advanced Editor → paste → Done → rename the query ChannelRevenue.

let Source = AllOrders, // "online", "ONLINE", " Store" → "Online", "Store"; then the one real typo CleanChannel = Table.TransformColumns(Source, {{"Channel", each Text.Proper(Text.Trim(_)), type text}}), FixTypo = Table.ReplaceValue(CleanChannel, "Onlin", "Online", Replacer.ReplaceValue, {"Channel"}), // Qty: "N/A" and blank → null (unknown). Discount %: blank → 0 (no discount) Typed = Table.TransformColumns(FixTypo, { {"Qty", each try Number.From(_) otherwise null, type nullable number}, {"Unit Price", Number.From, type number}, {"Discount %", each (try Number.From(_) otherwise null) ?? 0, type number}}), // revenue only counts completed orders with a known quantity Completed = Table.SelectRows(Typed, each [Status] = "Completed" and [Qty] <> null), WithTotal = Table.AddColumn(Completed, "Line Total", each [Qty] * [Unit Price] * (1 - [Discount %] / 100), type number), ByChannel = Table.Group(WithTotal, {"Channel"}, { {"Orders", each Table.RowCount(_), Int64.Type}, {"Revenue", each Number.Round(List.Sum([Line Total]), 2), type number}}) in ByChannel
ChannelOrdersRevenue (₹)
Online2653,471.38
Store1828,604.00

Check the arithmetic, not just the output: 49 rows − 3 cancelled (ORD2005, ORD2016, ORD2042) − 2 unknown quantities (ORD2006, ORD2011) = 44 orders = 26 + 18. If your total isn't 44, click each step in turn and find where the count changes unexpectedly. Checking row counts step by step like this is the most useful debugging habit in Power Query.

Why hand-write it at all? Every step here could be clicked, except that the UI can't express "blank discount means 0, but blank quantity means unknown" in one pass. Writing it makes each decision visible in a comment, where the next analyst can read it and challenge it.

Custom functions and parameters

A function is a query that takes inputs. Home → New Source → Blank Query → Advanced Editor:

(qty as nullable number, unitPrice as number, discountPct as nullable number) as nullable number => qty * unitPrice * (1 - (discountPct ?? 0) / 100)

Rename it fnLineTotal. Use it from any query: Add Column → Invoke Custom Function, or a custom column = fnLineTotal([Qty], [Unit Price], [Discount %]). The discount rule is now defined once. Change it there, and every query using it follows. For a function with real branching logic, see fnParseOrderDate on the next page.

A parameter is a named value every query can use. The classic use is the data folder, so moving the files doesn't mean editing every Source step:

  1. Home → Manage Parameters → New → Name DataFolder, Type Text, Current Value C:\Data\
  2. In each query's Source step, replace the hard-coded path: File.Contents(DataFolder & "PQ_Practice_Orders.csv")
  3. Files moved? Change DataFolder once, then refresh

Practice: read, write, fix

All on AllOrders unless noted. Try each one before opening the solution.

1 · Custom column: the state from Ship City ("Bangalore, Karnataka" → "Karnataka")
= Text.Trim(Text.AfterDelimiter([Ship City], ","))

7 distinct states. The Text.Trim removes the space after the comma. Splitting on ", " (comma + space) instead also works, but breaks as soon as one row is typed without the space.

2 · Custom column: the color code from Product Code ("SKU-1001-RED" → "RED")
= Text.End([Product Code], 3) // sturdier if codes ever get longer colors: text after the 2nd hyphen (index 1 = second occurrence) = Text.AfterDelimiter([Product Code], "-", 1)
3 · In ChannelRevenue's WithTotal step: keep only Online orders worth more than ₹2,000. How many?
BigOnline = Table.SelectRows(WithTotal, each [Channel] = "Online" and [Line Total] > 2000)

12 rows. Largest: ORD2021 at ₹5,396.40 (4 × ₹1,499 less 10%). Remember to change in to BigOnline, or add the step before ByChannel and point ByChannel at it.

4 · Add a "Pricing" column: "Promo" when Discount % is 10 or more, else "Full price". How many of the 44 completed orders are Promo?
= if [Discount %] >= 10 then "Promo" else "Full price"

17 Promo. Add it after Typed, where Discount % is a number and blanks are already 0. Added earlier, the column may still hold text or a null, and the comparison errors.

5 · This query won't run. Find all three bugs.
let Source = AllOrders, Trimmed = Table.TransformColumns(Source, {{"First Name", text.trim}}) Online = Table.SelectRows(Trimmed, each [Channel] = "Online"), in Onlin

(1) text.trim → Text.Trim (case). (2) The Trimmed line is missing its trailing comma, and the Online line has one it mustn't have before in. (3) in Onlin names a step that doesn't exist → in Online. Bonus: even fixed, it returns 24 rows, yet 28 of the 49 orders were placed online. Where are the other 4? (2 × "online", 1 × "ONLINE", 1 × "Onlin": the filter is case-sensitive and exact, so clean Channel before filtering on it.)
